# ローカルで話者分離を評価する

Settingsの末尾にある「詳細: 話者分離の評価」を開きます。通常の録音・文字起こしを変更する機能ではありません。モデルを実行せず、手元のRTTMだけをCPUで比較します。

1. 録音を選びます。仮説はその録音の `postprocess/nemotron.rttm` です。別の結果を比較するときは「仮説RTTMを選ぶ」で指定します。
2. 「人手で確認した参照に対する評価」か「モデル間の不一致」を選び、OSのファイル選択で参照RTTMを指定します。初期値はモデル間の不一致です。前者を使う場合、参照が人手で確認済みであることは利用者が確認してください。RTTMから確認履歴を自動判定することはできません。
3. 録音全体か開始・終了秒、collar全幅、参照の同時発話を含むかを指定して「評価を実行」します。空の秒数欄は開始0秒、終了は録音末尾、collarは0秒です。
4. 結果で内訳と話者対応を確認します。不一致区間の「聞き直す」は既存の録音プレイヤーをその時刻で開きます。Play / Pauseで再生してください。録音中は既存のガードにより再生を拒否します。区間は50件ずつ追加表示できます。
5. 「この実行結果をJSONで保存」を押すと録音の `postprocess/evaluations/evaluation-*.json` に保存します。表示・保存する条件は直前の実行時点のスナップショットです。条件欄を編集したときは再実行してください。JSONには入力ファイルパス、RTTM内容のSHA256、条件、アルゴリズム版、話者対応、全不一致区間を含みます。音声・元RTTM・文字起こし・手動注釈は書き換えません。保存失敗時は表示した結果を再保存できます。既存の結果は上書きしません。

## 数値の意味

人手参照のDERは `(miss + false alarm + confusion) / 参照話者秒数` です。accuracyではなく誤り率で、誤検出が多い場合は100%を超えます。モデル間では同じ方向付き計算を「不一致率」と表示・保存し、DER欄はnullです。参照モデルを入れ替えると値が変わり得ます。モデルの優劣・精度の証明にはなりません。

参照・仮説を評価範囲（UEM）に制限し、参照境界のcollarと指定時の参照同時発話を除いてから、一度だけ会議全体の最適な一対一話者対応をHungarian法で求めます。評価範囲を絞ると、その範囲全体で対応を求め直します。区間ごとの対応の取り直しは行いません。正の共起がない対応は省略し、余った話者は未対応です。同点の対応には複数の最適解があります。

区間の参照話者数をR、仮説話者数をH、対応の一致数をCとすると、秒数内訳は `max(R-H, 0)`、`max(H-R, 0)`、`min(R,H)-C` に区間長を掛けます。参照話者秒数は同時に2人が話す1秒を2秒と数えます。「評価対象時間」は除外後の壁時計時間で、無音も含みます。参照話者時間が0（参照が空、全区間除外など）の率は未定義/nullです。0%とは表示しません。無音に仮説だけがあるとfalse alarmに加算します。

collarは**全幅**です。例えば0.25秒なら、正規化した参照区間の開始・終了のそれぞれで前後0.125秒を両入力から除外します。UEMで切った端に新たなcollarは作りません。UEM・区間は元の録音基準の半開区間 `[start,end)` です。同一話者の重複・接する区間は統合し、重複を二重に数えず、人工的な内部境界にcollarを追加しません。同時発話除外は異なる参照話者が2人以上いる区間が対象です。

定義は [pyannote.metricsのDER実装](https://github.com/pyannote/pyannote-metrics/blob/develop/src/pyannote/metrics/diarization.py)、[UEMとcollar実装](https://github.com/pyannote/pyannote-metrics/blob/develop/src/pyannote/metrics/utils.py) と照合しています。12個の手計算fixtureの内訳を、既存ローカルのpyannote.metrics 4.1でも独立確認しました。ゼロ参照の率は意図的にpyannoteのスカラー代替値と異なり未定義とします。同一話者の重複は上述の統合規則を適用します。fixtureは `crates/kikimimic-core/tests/fixtures/diarization_evaluation.json` にあります。

## 入力と上限

UTF-8の10フィールド `SPEAKER` RTTM、単一録音ID、channel 1を受け付けます。各入力の録音IDは異なっていても構いませんが、両入力は同じ録音の時刻に整列済みである必要があります。時刻ずれを自動補正しません。空行と先頭 `#` のコメントは無視します。空ファイルは無音注釈として有効ですが、未選択・ファイル欠損はエラーです。

未知の行、欠損フィールド、非有限値、負時刻、長さ0以下、録音末尾を超える区間、複数録音/チャンネルはエラーです。評価範囲外でも録音内の有効区間はUEMで切り取ります。大きな入力でUIを塞がないよう、一覧読込・入力読込・計算・保存はバックグラウンドで行います。

各RTTMは8 MiB・20,000区間・128話者以内、ID・話者名は128バイト以内です。Hungarian法は最大128×128でO(n³)。時刻を1msずつ列挙せず区間境界を走査します。中間状態は延べ100万話者ラベル、共起計算は5,000万組、不一致出力のラベル文字列は32 MiBを上限とし、超過時は評価範囲を小さくするエラーを返します。部分結果を完成結果として保存しません。

## Core APIとCLI再現

公開APIは `kikimimic_core::diarization_evaluation::evaluate(reference, hypothesis, options)` です。OS・GPU・UI・network・Pythonを必要としません。coreのUEMは複数区間の和集合にも対応します。

```sh
nix develop -c cargo run -p kikimimic-core --example evaluate_diarization -- reference.rttm hypothesis.rttm options.json
```

`options.json` の例（この数値は実行条件で、評価結果ではありません）:

```json
{
  "mode": "human_reference",
  "recording_duration": 600.0,
  "uem": [{"start": 20.0, "end": 300.0}],
  "collar": 0.25,
  "skip_overlap": false
}
```

CLIは結果JSONを標準出力に出します。録音IDやhashは入力の同一性を追跡するためのもので、人手参照の正しさやRTTMと音声の整列を保証するものではありません。
