# 外部音声の取り込み

録音一覧の「WAV / M4A / MP3を取り込む」から、OSのファイル選択で音声を選びます。複数選択した場合は1ファイルにつき1録音を作り、順番に処理します。取り込み先は既存の録音フォルダー（`KKM_RECORD_DIR`も有効）です。元ファイルは書き換えません。M4A/MP3はmacOS標準のAudioToolboxコマンド`/usr/bin/afconvert`でローカルにデコードします。ffmpegのインストールは不要です。

ASRモデル、翻訳モデル、話す言語・訳す言語・相互翻訳、用語辞書はキュー投入時に保存されます。後から設定を変えても、投入済みのファイルや再試行の設定は変わりません。モデルは通常のモデル画面で導入済みのものを使います。取り込みからモデル取得は行いません。未導入のモデルや対応しない音声はキューにエラーを表示します。

キューには待機・実行中・完了・失敗・スキップが表示されます。1件失敗しても次のファイルを処理し、「失敗分を再試行」で再実行できます。「現在のファイル完了後に停止」は現在のファイルを完了して待機分を残します。アプリを終了した場合、処理中のファイルは次回起動時に待機へ戻ります。「待機分を再開」でファイルの先頭から処理します。**ファイル途中からの再開ではありません。** ライブ録音中や話者分離中は取り込みを開始できません。待機分はそれらの終了後に手動で再開できます。取り込み中もライブ録音・話者分離は開始できません。

分割WAVを一つの会議にする場合は、別の「WAVを1会議に結合」を選びます。選択後に表示される順序を↑↓で変更し、不要なファイルを除いてから「結合してキューに追加」を押してください。サンプルレート・チャンネル数・ビット深度・サンプル形式が異なるWAV、WAV以外のファイルは処理前に拒否します。これは指定順の連結です。実時間の隙間を復元したり、複数機器を同期したりはしません。結合グループ全体を停止・再試行の単位にします。

完成した録音は通常と同じ48kHz mono PCM16の`mic.wav`・`mix.wav`、既存形式の`transcript.jsonl`です。文字起こしは最大30秒の音声片を逐次処理し、原音上のサンプル位置を時刻に加算します。リサンプラーのフィルター遅延と末尾のパディングを除き、音声の先頭と長さを保持します。区切りは語の境界を保証しないため、境界付近の認識品質は実モデル・実音声で確認してください。単語単位時刻は生成しません。無音ファイルは空の文字起こしで保存します。

入力内容のSHA256、選択順、結合モード、処理設定、処理バージョンが一致する完成録音は再利用してスキップします。入力のパスが変わっても同じ内容であれば再利用します。完成録音の音声・元の文字起こしが変更されていた場合は上書きせずエラーにします。取り込み後の話者分離など、`postprocess/`に置く派生処理はこの判定から独立しています。

完成済みファイルが見つからない場合は再起動時に失敗へ戻します。一部だけ失われた録音フォルダーは残してエラーにするため、ファイルを復元するか、不完全なフォルダーを利用者が除いてから再試行してください。

キューはアプリのデータディレクトリの`imports.json`へ保存します。音声と文字起こしを録音フォルダー内の`.imports/`以下で作り、検証してからディレクトリのrenameで公開します。完成前の成果は録音一覧に出しません。中断したプロセスの一時成果が`.imports/`に残る場合があります。完成録音を公開した直後に終了してキュー更新が間に合わなくても、再開時に`import.json`から完成を確認してスキップできます。キューファイルが壊れている場合はエラーを示し、自動で破棄しません。

通常のWAV上限（約4GiB）を超える音声はエラーにします。長時間音声の音声サンプルは全体をメモリへ読み込みませんが、デコード・正規化用の一時ディスク容量は必要です。キューや録音一覧の履歴・文字起こしは既存アプリと同様に管理されます。

検証は合成WAV、合成MP3、macOS上で生成したM4Aとfake engineで行っています。実モデルの認識品質、GPUI上でのファイル選択・操作の実機受け入れは別途必要です。
