# 実会議の品質評価プロトコル (#30)

## 測定前に固定するもの

実行ごとに run.json を保存し、commit、OS、CPU/GPU/RAM、電源状態、モデル名・量子化・ハッシュ・ライセンス、エンジンrevision、設定、GPUの他負荷、録音装置・サンプルレート・ヘッドホン有無、音声SHA256・利用許諾を記録する。ダウンロードは別途同意が必要。キャッシュ済みモデルのみ使用する。

同じ音声に対して ASR+翻訳のみと要約/Q&A併用を各3回、cold/warmを分離して測定する。各条件の平均、p50/p95、最大、欠測数、失敗数、破棄数、停止待ち時間、プロセス群全体のピークRSSを報告する。試行間を混ぜず、母数も併記する。

初回試験の暫定基準は部分表示p95 1500ms、発話終了から確定p95 3000ms、確定から翻訳p95 3000ms、破棄0、成功率99%以上とする。製品の保証値ではない。機器別のRSS上限と停止待ち上限は run.json に測定開始前に記入する。未記入の試験は探索扱いとし合否判定しない。基準変更時は新しいprotocol revisionで再測定する。

## 共通フィクスチャと採点

#21 と同じ fixture ID、音声、発話ID、根拠付き正解を使う。日本語・英語・日英混在をそれぞれ10分/60分で用意し、静音・環境ノイズ・同時発話を含める。機微情報のない許諾済み音声を用い、出典と許諾を同梱する。現時点でこのコーパスは未収集。

正解JSONLは id、start_ms、end_ms、source(mic/system)、speaker(S0等)、language、text、固有名詞、意味単位、決定/撤回/担当/期限とその根拠IDを持つ。人名確認前に話者IDを人物名へ変換しない。2名が独立採点し、不一致と裁定を残す。

日本語はUnicode文字単位CER、英語は空白単位WERを併記する。前処理（NFC、句読点、大小文字）の規則を固定し、混在言語を単一WERで比較しない。固有名詞一致率、翻訳意味単位保持率、原文にない情報の件数を採点する。暫定品質基準はCER/WER各15%以下、固有名詞90%以上、意味保持95%以上、架空の決定/担当/期限0件。要約/Q&Aは#21の根拠一致・取りこぼし採点を再利用する。

mic/system の入力元と話者は別軸。各入力元内の複数話者、重複、ヘッドホン有無を別条件として報告する。リアルタイム話者ラベルは#8で方式と日本語性能を確認後に判断する。現在の Event::PostProcess は録音後の処理であり、リアルタイム成立の証拠にならない。

## 遅延アダプタと集計

`node scripts/meeting-metrics.mjs observations.jsonl > report.json`

観測JSONLは1発話1行、idとoutcome(success/failed/dropped/unmeasured)を必須とする。任意の非負有限数 first_partial_ms は音声開始→最初の表示、finalization_ms は音声終了→確定表示、translation_ms は確定表示→翻訳表示。peak_rss_mib はその発話の観測区間のプロセス群ピーク。未観測は省略し、0で補完しない。失敗/破棄に翻訳遅延を入れない。各run・条件別にファイルを分ける。分位点はnearest-rank、欠測・失敗は分母から隠さない。メモリはmaxも使う。

現行Event::Transcript/Translationには表示時刻がないため、保存イベントだけから表示遅延は復元できない。観測アダプタで単調時計をUI描画時に記録し、音声時刻と同一時計へ校正する必要がある。このPRは自動収集を実装しない。要約更新・停止待ちはrun単位で別途記録する。音声認識誤り、意味保持、話者品質は人手採点であり、この集計ツールは計算しない。

検算: `node scripts/meeting-metrics.mjs --self-test`。合成値のみを使用し、モデルの品質や速度の証拠にはしない。
