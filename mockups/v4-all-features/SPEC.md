# Kikimimic v4 — 全機能モック 30 案 共通仕様

前提: いまオープンな PR（#32〜#52）をすべて取り込んだ状態のアプリを、操作できる HTML モックで表す。
30 案は **情報設計・画面構成・導線の違い** で比べるためのもので、見た目の個性では差をつけない。

## 注文（ユーザーの要望。すべての案で守る）

- 今の UI の雰囲気を踏襲（`app/src/window.rs` の GPUI 版: 白地、`#d0d7de` の枠線、角丸 6px、選択中は黒地白字のボタン、灰色のメタ情報、青い訳文、黄色の通知、暗いカットインカード）
- ミニマル / ごちゃつかない（1 画面に出すものを絞る。補助情報は折りたたみ・二次画面へ）
- ユースケースを意識（会議の直前・最中・直後・後日の振り返り、という時間の流れで導線を設計）
- 統一感のある操作と UI パーツ（`shared/kit.css` のパーツだけで組む。新しい色・影・角丸・フォントを足さない）
- 奇抜な個性は不要（グラデーション、ガラス、イラスト、絵文字アイコン、派手なアニメーションは使わない）

## ファイル規約

- 各案は `NN-slug.html`（NN = 01〜30）。1 ファイルで完結し、`shared/kit.css` と `shared/data.js` だけを読む:
  `<link rel="stylesheet" href="shared/kit.css">` / `<script src="shared/data.js"></script>`
- 外部 CDN・フォント・画像は使わない。ビルド不要、file:// で開いて動く。
- 画面は `.win`（デスクトップのウィンドウ枠）の中に描く。UI 文言は日本語。
- 左上に `<div class="mock-nav"><a href="index.html">← 一覧</a> · NN 案名</div>` を置く。
- `<head>` に `<meta name="kkm-concept" content="1 行の説明">` を書く（一覧ページが読む）。
- 案ごとの CSS は `<style>` にレイアウトだけ書く。色は kit.css の変数だけを使う。
- モックデータとフェイクエンジンは `window.KKM`（shared/data.js）を使う。データを複製しない。
- JS エラーを出さない。全機能に、最低 1 つは実際に動くクリック経路があること。

## 主ユーザー（必読・全案の評価軸）

- メインの利用者はこのアプリの作者本人。毎日複数の会議があり、オンラインとオフライン合わせて **月 90 件ほど**（1 日 4〜5 件）
- オンライン会議: Kikimimic でライブ録音（2 レーン）
- オフライン会議: 録音したものを **あとで文字起こししてから議事録を作る**（取り込み #51 / 対面モードの保存 #39 → 文字起こし → 話者 → 議事録 #38）
- 文字起こしは議事録のほかに **Obsidian で Markdown として管理** している

すべての案は、各自の仮説を保ったまま、この人の次の問いに答えること:
1. 1 日 4〜5 件・月 90 件の量で、一覧と検索が破綻しないか（`KKM.recordings` は約 90 件ある。全件を描いても重くならない一覧にする。日付のまとまり・処理状態の絞り込みを考える）
2. オフライン会議の「取り込み → 文字起こし → 議事録」の後処理が、何回のクリックで終わるか。どこで止まっているかが分かるか（`rec.status` を使う）
3. Obsidian へ MD を置く流れがどこにあるか（`KKM.settings.obsidian`、`KKM.exportText(rec, "obsidian")` が frontmatter 付きの MD を返す。書き出しは録音ごとの手動操作と、議事録ができたら自動、の両方）。Obsidian 連携は PR には無い拡張だが、MD 書き出し（#49）と検索フォルダ（#44）の延長として全案に入れる

## 各案のコンセプトと理由（必読・最優先）

似た UI を 30 個並べても意味がない。各案は **1 つの設計仮説** を検証するためにある。
次の 4 点が画面を見ただけで伝わること。伝わらない案、ほかの案と画面が入れ替わっても気づかない案は失格。

- **誰が・いつ**: 想定するユーザーと場面（会議の直前 / 最中 / 直後 / 後日）
- **仮説**: 「〜だから、〜を主役にすると〜が速く・迷わずできる」
- **違い**: ほかの案と見比べて、ひと目で分かる構造上の違い（ナビの形、起動直後の画面、主操作の場所、詳細の分け方）
- **捨てるもの**: この構成で不便になること（トレードオフ）。隠す場所に置いた機能は、どこにあるか分かるようにする

各ファイルの `<head>` に次の 3 つを書く（一覧ページと比較表に使う）:
`<meta name="kkm-concept" content="1 行のコンセプト">`
`<meta name="kkm-why" content="仮説と理由（誰が・いつ・なぜ）">`
`<meta name="kkm-tradeoff" content="捨てるもの">`
さらに画面右下に小さな「この案について」ボタン（`.btn.sm.ghost`）を置き、押すと `.sheet` で上の 3 点を表示する。UI 本体には説明文を書かない。
